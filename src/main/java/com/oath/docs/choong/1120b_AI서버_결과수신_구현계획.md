# 1120b AI 서버 결과 수신 구현 계획 및 결과

- **작성일:** 2025-11-20
- **최종 수정일:** 2025-11-20

## 1. 목표

Java 서버가 Python AI 서버로 통계 데이터를 전송(Push)한 후, AI 서버로부터 분석이 완료된 '요약 보고서'를 다시 수신(Fetch)하여 `Plan` 엔티티에 저장하는 기능을 구현한다.

## 2. 선행 조건

- `1120a` 계획에 따라, `PlanCompletionListener`에서 `MetricsPushService`를 호출하여 AI 서버로 데이터를 전송하는 기능이 정상적으로 동작해야 한다.

## 3. 구현 계획 및 결과

### 3.1. `Plan` 엔티티에 요약 필드 추가 - **[완료]**
- `Plan.java`에 AI가 생성한 텍스트 요약 보고서를 저장할 `summary` 필드를 추가함.

### 3.2. `application-local.yml`에 요약 API URL 변수 추가 - **[완료]**
- `ai.server` 섹션에 `summary-url`과 `summary-fetch-delay-ms` 변수를 추가하여 설정을 외부화함.

### 3.3. `MetricsPushService`에 요약 보고서 수신 메서드 추가 - **[완료]**
- `fetchAndSaveSummary(Long planId)` 메서드를 생성함.
- 일시적인 네트워크 오류에 대응하기 위해 Spring Retry의 `@Retryable`을 적용하여 안정성을 높임.

### 3.4. `PlanCompletionListener`에서 새 메서드 호출 - **[완료]**
- `TaskScheduler`를 사용하여, 설정된 시간만큼 지연된 후 `fetchAndSaveSummary`를 비동기적으로 호출하도록 구현함. `Thread.sleep()`을 회피하여 시스템 리소스를 효율적으로 사용함.

## 4. 테스트 및 검증 - **[완료]**
- **결과:** Java 서버와 Python 서버 간의 실제 통신 테스트를 성공적으로 완료함. `planId=2`인 약속이 완료되자, 5초 후 AI 서버로부터 요약 보고서를 정상적으로 수신하여 `PLAN_TB` 테이블의 `SUMMARY` 컬럼에 저장되는 것을 확인함.

## 5. 향후 개선 계획: 폴링(Polling) 방식 도입

### 5.1. 현재 방식의 문제점

- 현재 구현은 `TaskScheduler`를 사용하여 **고정된 시간(5초)을 대기**하는 방식이다.
- 이 방식은 AI 서버의 분석 시간이 5초보다 길어지면 실패하고, 5초보다 짧으면 불필요하게 기다리는 비효율이 발생할 수 있다.

### 5.2. 목표

- 고정 시간 대기 방식 대신, AI 서버의 작업 상태를 주기적으로 확인(Polling)하여, 분석이 완료된 시점에 즉시 결과를 가져오는 더 안정적이고 효율적인 방식으로 개선한다.

### 5.3. 세부 구현 계획

#### 1) Python 서버 API 추가 (협의 필요)
- Python 서버에 분석 작업의 상태를 조회할 수 있는 새로운 API 엔드포인트가 필요하다.
- **요청:** `GET /metrics/report/{planId}/status`
- **응답:**
    - 작업 중: `{"status": "PROCESSING"}`
    - 작업 완료: `{"status": "COMPLETED"}`
    - 작업 실패: `{"status": "FAILED"}`

#### 2) `MetricsPushService`에 폴링 로직 구현
- **메서드 생성:** `pollAndFetchSummary(Long planId)` 라는 새로운 메서드를 생성한다.
- **내부 로직:**
    1. `TaskScheduler`를 사용하여 **주기적인(fixed-rate) 폴링 작업을 예약**한다. (예: 3초마다 실행)
    2. 예약된 작업은 AI 서버의 상태 조회 API(`.../status`)를 호출한다.
    3. 응답 상태가 `COMPLETED`이면, 폴링을 중단하고 즉시 `fetchAndSaveSummary(planId)`를 호출한다.
    4. 응답 상태가 `PROCESSING`이면, 아무것도 하지 않고 다음 폴링을 기다린다.
    5. 일정 횟수(예: 10번) 이상 폴링해도 `COMPLETED`가 되지 않거나, `FAILED` 응답을 받으면 폴링을 중단하고 에러 로그를 남긴다.

#### 3) `PlanCompletionListener` 수정
- 기존의 `TaskScheduler`를 사용한 단일 지연 예약 로직을, 새로 만든 `pushService.pollAndFetchSummary(planId)`를 호출하는 코드로 대체한다.

### 5.4. 기대 효과
- AI 서버의 분석 시간에 관계없이, 작업이 완료되는 즉시 결과를 가져올 수 있어 시스템의 효율성과 안정성이 크게 향상된다.
- 'Fire-and-forget' 방식의 단점을 보완하여, AI 서버 연동 파이프라인의 신뢰도를 높인다.
