# `place_tag_plan` 도메인 설명서

이 문서는 `place_tag_plan` 패키지 하위의 각 도메인 역할과 관리자 API 사용법을 설명합니다.

## 1. 도메인 구조 및 역할

이 패키지는 장소(Place)와 태그(Tag), 그리고 약속(Plan)과 태그(Tag) 간의 N:N 관계를 관리하는 도메인 모델을 포함합니다.

- **`place`**: 장소의 정보를 관리하는 도메인입니다. (e.g., 이름, 주소, 좌표 등)
- **`tag`**: 장소나 약속에 붙일 수 있는 태그 정보를 관리하는 도메인입니다. (e.g., "맛집", "스터디", "분위기 좋은")
- **`place_tag`**: `Place`와 `Tag`의 N:N 관계를 위한 중간 테이블(Join Table) 엔티티입니다.
- **`plan_tag`**: `Plan`과 `Tag`의 N:N 관계를 위한 중간 테이블(Join Table) 엔티티입니다.

## 2. 관리자 API 사용법

관리자는 다음 API 엔드포인트를 통해 각 도메인 데이터를 수동으로 관리할 수 있습니다.

### 2.1. 장소 관리 (`PlaceAdminController`)

- **Base URL**: `/admin/places`

#### `POST /admin/places`
- **설명**: 새로운 장소를 생성합니다.
- **Request Body**:
  ```json
  {
    "name": "강남역 토끼정",
    "address": "서울 서초구 서초대로73길 12",
    "lat": 37.5000123,
    "lng": 127.0254876,
    "description": "크림 카레 우동이 유명한 퓨전 일식당",
    "imageUrl": "http://example.com/image.jpg"
  }
  ```

#### `PUT /admin/places/{placeId}`
- **설명**: 기존 장소의 정보를 수정합니다.
- **Request Body**: 위와 동일

#### `DELETE /admin/places/{placeId}`
- **설명**: 특정 장소를 삭제합니다.

---

### 2.2. 태그 관리 (`TagAdminController`)

- **Base URL**: `/admin/tags`

#### `POST /admin/tags`
- **설명**: 새로운 태그를 생성합니다.
- **Request Body**:
  ```json
  {
    "name": "맛집"
  }
  ```

#### `PUT /admin/tags/{tagId}`
- **설명**: 기존 태그의 이름을 수정합니다.
- **Request Body**: 위와 동일

#### `DELETE /admin/tags/{tagId}`
- **설명**: 특정 태그를 삭제합니다.

---

### 2.3. 장소-태그 관계 관리 (`PlaceTagAdminController`)

- **Base URL**: `/admin/place-tags`

#### `POST /admin/place-tags`
- **설명**: 특정 장소에 태그를 연결합니다.
- **Request Body**:
  ```json
  {
    "placeId": 1,
    "tagId": 3
  }
  ```

#### `DELETE /admin/place-tags`
- **설명**: 특정 장소와 태그의 연결을 해제합니다.
- **Request Body**: 위와 동일

---

### ※ 참고: `plan_tag` 관리

`plan_tag` 도메인은 별도의 관리자 컨트롤러를 가지지 않습니다. 약속(Plan)에 태그를 연결하는 로직은 `Plan` 도메인의 비즈니스 로직 내에서 `PlanTagRepository`를 통해 처리됩니다.
