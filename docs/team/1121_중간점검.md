# 1121: 중간 점검 및 장기 계획 (11/24 이후)

## 1. 보고서 종합 요약

프로젝트는 초기 기획의 방대함에서 MVP 중심으로 범위를 조정한 후, 핵심 기능 구현에 집중하고 있음. 특히 "실시간 지도"와 "AI 요약" 기능은 중요한 축을 담당하고 있음. 피드백들은 프로젝트의 방향성, 기술적 깊이, 그리고 팀원들의 성장 기회에 초점을 맞추고 있음.

**현재까지의 진행 상황 (충희님 역할 중심):**
*   AI 요약 보고서 제공 API 구현 및 폴링 방식 고도화 완료.
*   실시간 지도 기능의 서버 측 핵심 로직 (위치 수신 → 이벤트 발행 → WebSocket 전송) 구현 완료.
*   `DataInitializer` 관리 및 샘플 데이터 생성.
*   `LIVE_MAP_API.md` 문서화.

**주요 피드백 및 고려 사항:**
1.  **"뾰족한" 아이덴티티:** 앱의 정체성을 명확히 하는 것이 중요. 특정 타겟(동호회, 스터디 등)에 집중하여 기능을 고도화할 필요성.
2.  **포트폴리오 가치:** "보여줄 만한 결과물"을 많이 만드는 것이 중요. 기술적 깊이와 사용자 경험을 동시에 고려.
3.  **데이터의 가치 및 활용:** 수집된 데이터를 활용한 의미 있는 통계/분석 기능(AI 요약 포함) 고도화 중요.
4.  **성능 최적화 및 유지보수:** `TrackService` 최적화처럼 성능과 유지보수성을 지속적으로 고려.
5.  **클라이언트 연동:** 실시간 지도 기능의 핵심은 클라이언트와의 성공적인 연동.

## 2. 장기 계획 (11/24 이후)

### 장기 목표:
*   **핵심 기능 완성도 극대화:** 실시간 지도, AI 요약 등 핵심 기능의 사용자 경험을 완벽하게 구현하고, 기술적 깊이를 확보하여 포트폴리오 가치를 높임.
*   **데이터 기반 가치 창출:** 수집된 데이터를 활용하여 사용자에게 유의미한 정보(통계, 분석)를 제공하고, 이를 통해 앱의 "공정성" 가치를 강화함.
*   **확장성 및 유지보수성 확보:** 향후 기능 확장을 고려한 아키텍처 설계 및 코드 품질을 유지함.

### 세부 계획 (우선순위 및 역할 고려):

**1. 실시간 지도 기능 완성 및 고도화 (성빈님과 협업)**
    *   **목표:** 서버-클라이언트 간 실시간 위치 공유 및 이벤트 알림의 완벽한 연동.
    *   **세부 과업:**
        *   **클라이언트 연동 지원:** `LIVE_MAP_API.md` 문서를 기반으로 성빈님과 긴밀히 협업하여 Flutter 클라이언트의 위치 전송 및 WebSocket 구독 기능 구현을 지원.
        *   **통합 테스트 및 디버깅:** 두 명 이상의 사용자가 참여하는 시나리오로 실시간 지도 기능의 통합 테스트를 주도하고, 발생 가능한 모든 문제(네트워크 불안정, 백그라운드 전환 등)를 디버깅하여 안정성 확보.
        *   **UI/UX 개선 제안:** 클라이언트 측에서 실시간 마커 렌더링 부하를 줄이는 최적화 방안을 함께 고민하고, 사용자에게 더 나은 시각적 경험을 제공할 수 있는 방안을 제안.
        *   **테스트용 강제 이벤트 API 구현:** `PlanTestApiController`에 "도착", "정체" 이벤트를 강제로 트리거할 수 있는 API를 구현하여 클라이언트 개발 및 테스트 편의성 증대.

**2. AI 요약 보고서 기능 고도화 및 활용**
    *   **목표:** AI 요약 보고서의 내용 품질 향상 및 사용자에게 가치 있는 정보 제공.
    *   **세부 과업:**
        *   **AI 서버 연동 안정화:** AI 서버와의 통신에서 발생할 수 있는 엣지 케이스(네트워크 오류, AI 서버 응답 지연 등)를 처리하고, 재시도 로직 등을 통해 안정성 확보.
        *   **요약 내용 개선:** AI 요약 보고서가 단순히 약속 내용을 요약하는 것을 넘어, "누가 얼마나 지각했고, 누가 얼마나 일찍 왔는지" 등 앱의 핵심 가치인 '공정성'과 관련된 데이터를 포함하도록 AI 서버 개발팀과 협의 또는 자체 로직 보강.
        *   **요약 데이터 시각화/활용 방안 모색:** 요약된 텍스트 외에, 통계 데이터를 기반으로 한 그래프나 차트 등 시각화 요소를 클라이언트에서 어떻게 보여줄지 기획 및 제안.

**3. 데이터 기반 통계 및 분석 기능 강화**
    *   **목표:** 수집된 위치 및 약속 데이터를 활용하여 사용자에게 유의미한 통계 정보 제공.
    *   **세부 과업:**
        *   **개인별/그룹별 통계 리포트:** `totalLateMinutes`, `totalOnTimeArrivals`, `totalTravelDistance`, `totalTravelTime` 등 `Plan` 엔티티에 추가된 통계 필드를 활용하여 개인별/그룹별 약속 참여 패턴, 지각/정시 도착 비율, 이동 거리/시간 등의 리포트 API 구현.
        *   **Python 분석 서버 연동:** 미연결된 Python 분석 서버와의 연동을 주도하여, 복잡한 분석 대신 단순 통계라도 앱에 노출될 수 있도록 통합 범위 재산정 및 구현.
        *   **데이터 시각화 기획:** 클라이언트에서 이러한 통계 데이터를 어떻게 효과적으로 시각화할지 기획팀/디자인팀과 협의.

**4. 아키텍처 개선 및 유지보수성 강화**
    *   **목표:** 코드 품질 향상 및 확장성 있는 시스템 구축.
    *   **세부 과업:**
        *   **`TrackService` 리팩토링:** `TrackService`의 책임이 과도하게 커질 경우, `LocationProcessingService`와 같이 세분화된 서비스로 책임을 분리하는 리팩토링을 주도.
        *   **테스트 코드 작성:** 핵심 로직(위치 추적, AI 요약 등)에 대한 단위 테스트 및 통합 테스트 코드를 작성하여 코드의 안정성 및 유지보수성 확보.
        *   **문서화:** API 문서 외에, 핵심 로직에 대한 설계 문서나 기술 블로그 포스팅 등을 통해 기술적 깊이를 어필할 수 있는 자료를 준비.
