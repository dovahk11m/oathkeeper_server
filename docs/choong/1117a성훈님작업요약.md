# 성훈님 작업 요약 문서 (AI 연동 파트)

이 문서는 기존에 성훈님이 담당하셨던 Python AI 서버 연동 기능의 구조와 흐름을 정리한 문서입니다.

---

### 1. 개요

- **주요 목표**: Java 서버의 약속 데이터를 Python AI 서버로 보내 분석하고, 그 결과를 받아오는 기능 구현.
- **핵심 위치**: 프로젝트 내 `com.oath.domain.metrics` 패키지에 모든 관련 코드가 집중되어 있습니다.

---

### 2. 주요 아키텍처 및 데이터 흐름

AI 연동 기능은 총 3단계의 파이프라인 구조로 설계되어 있으며, `MetricsOrchestrationController`가 이 모든 과정을 지휘(Orchestration)합니다.

#### **1단계: 데이터 집계 (Rollup)**
- **담당**: `MetricsRollupService.java`
- **역할**: DB에 저장된 사용자의 원천 데이터(`LocationTrack`)를 읽어, AI 분석에 필요한 1차 통계 데이터(멤버별 이동 거리, 이동 시간 등)를 계산합니다.
- **결과**: 계산된 결과는 `ParticipantMetrics` 엔티티에 저장됩니다.

#### **2단계: 데이터 전송 (Push)**
- **담당**: `MetricsPushService.java`
- **역할**: 1단계에서 집계된 `ParticipantMetrics` 데이터를 Python AI 서버로 전송하여 분석을 요청합니다.
- **기술**: `RestTemplate`을 사용하여 동기 방식으로 HTTP 통신을 수행합니다.
- **AI 서버 엔드포인트**: `http://localhost:8001/metrics/analyze` (현재 코- 드에 하드코딩)

#### **3단계: 분석 결과 수신 (Fetch)**
- **담당**: `MetricsOrchestrationController.java`
- **역할**: AI 서버가 데이터 분석을 완료했을 것이라 가정하고, 분석된 '요약 보고서'를 요청하여 받아옵니다.
- **기술**: `WebClient`를 사용하여 비동기 방식으로 HTTP 통신을 수행합니다.
- **AI 서버 엔드포인트**: `http://localhost:8001/metrics/report/{planId}`

---

### 3. 주요 파일 및 역할

- **`MetricsOrchestrationController.java`**:
  - `POST /api/plans/{planId}/metrics/refresh` API를 통해 위 1~3단계의 전 과정을 순차적으로 실행시키는 지휘자 역할.
- **`MetricsRollupService.java`**:
  - 원천 데이터(위치 기록)를 가공하여 멤버별 통계(이동 거리/시간)를 계산하는 서비스.
- **`MetricsPushService.java`**:
  - 가공된 통계를 Python AI 서버로 전송(Push)하는 서비스.
- **`ParticipantMetrics.java`**:
  - 계산된 멤버별 통계를 저장하는 데이터베이스 엔티티(테이블).
- **`application-local.yml` (또는 코드 내부)**:
  - AI 서버의 주소(`http://localhost:8001`) 및 관련 설정이 위치합니다. (현재는 코드 내부에 하드코딩되어 있음)

---

### 4. 실행 및 테스트 방법

1.  Python AI 서버를 로컬 환경에서 **`8001` 포트**로 실행합니다.
2.  Postman과 같은 API 테스트 도구를 사용합니다.
3.  **`POST`** 메소드로 `http://localhost:8080/api/plans/{planId}/metrics/refresh` 형식의 요청을 보냅니다.
    - `{planId}`는 테스트할 약속의 ID로 대체합니다.
4.  요청 후, Java 서버 콘솔에 출력되는 로그를 통해 각 단계(Rollup, Push, Fetch)의 진행 상황과 성공/실패 여부를 확인합니다.

---

### ※ 2025-11-20 업데이트 사항

위 내용은 AI 연동 기능의 초기 설계이며, 최근 다음과 같이 아키텍처가 변경되었습니다.

-   **자동화된 실행:** 이제 모든 과정은 `MetricsOrchestrationController`를 통해 수동으로 실행되지 않습니다. 대신, 약속이 완료되면 `PlanCompletionListener`가 이벤트를 받아 **자동으로, 비동기적으로** 모든 단계를 실행합니다.
-   **URL 외부화 완료:** AI 서버의 URL은 더 이상 코드에 하드코딩되어 있지 않고, `application-local.yml`의 `ai.server.url` 속성을 통해 관리됩니다.
-   **결과 수신 로직 위치:** 분석 결과 수신(Fetch) 기능은 아직 구현되지 않았으나, 구현 시 `PlanCompletionListener`가 `MetricsPushService`의 관련 메서드를 호출하는 방식으로 진행될 예정입니다.

따라서, 현재 시스템의 동작을 이해하려면 위 초기 설계와 함께 이 업데이트 사항을 반드시 참고해야 합니다.
