# 1119a: 실시간 지도 기능 서버 로직 구현 계획 및 결과

- **작성일:** 2025-11-19
- **최종 수정일:** 2025-11-20
- **상태:** **구현 완료**

---

## 1. 상황 설명

- **AS-IS:** 클라이언트로부터 위치 정보를 받아 DB에 저장하는 기능(`TrackService`)과, WebSocket 통신을 위한 통로(`LiveMapSocketConfig`)는 이미 존재했음.
- **문제점:** DB에 위치가 저장되어도, 이 정보가 WebSocket 구독자에게 자동으로 전송되지 않는, 즉 두 기능 사이의 **'연결고리'가 없는 상태**였음.

## 2. 주요 목표

- 데이터 수집과 실시간 통신 통로 사이의 끊어진 연결고리를 이어, 사용자의 실시간 위치 정보가 해당 약속의 구독자들에게 WebSocket을 통해 자동으로 전송(Broadcast)되는 기능을 구현한다.

---

## 3. 해결 전략: 이벤트 기반 아키텍처 도입

`TrackService`가 `LocationTrack`을 저장하는 시점에 이벤트를 발생시키고, 별도의 리스너가 이 이벤트를 받아 WebSocket으로 메시지를 전송하도록 역할을 분리하여, 도메인 간의 결합도를 낮추고 비동기적으로 처리한다.

---

## 4. 세부 구현 계획

### 4.1. `LocationUpdatedEvent` 생성

-   **목적:** 새로 업데이트된 위치 정보를 담는 이벤트 객체를 정의한다.
-   **위치:** `com.oath.domain.locationevents.event`
-   **포함 데이터:**
    -   `Long planId`: 어떤 약속에 대한 위치 정보인지 식별
    -   `Long memberId`: 누가 보낸 위치 정보인지 식별
    -   `String username`: 사용자의 이름
    -   `String profileImageUrl`: 사용자의 프로필 이미지 URL
    -   `Double lat`: 위도
    -   `Double lng`: 경도
    -   `LocalDateTime lastLiveTs`: 위치 정보가 기록된 시간

### 4.2. `TrackService` 수정

-   **목적:** 위치 정보를 DB에 저장한 직후, 위에서 정의한 `LocationUpdatedEvent`를 발행(publish)한다.
-   **수정 대상:** `TrackService.ingestTracks` (또는 유사한 이름의 메서드)
-   **추가 로직:**
    -   `LocationTrack` 저장 후, 해당 정보를 바탕으로 `LocationUpdatedEvent` 객체를 생성한다.
    -   Spring의 `ApplicationEventPublisher`를 사용하여 이벤트를 발행한다.

### 4.3. `LocationUpdateListener` 생성

-   **목적:** `LocationUpdatedEvent`를 수신하여, 최종 데이터를 가공하고 WebSocket으로 전송한다.
-   **위치:** `com.oath.domain.locationevents.event.listener`
-   **주요 로직 (`handleLocationUpdate` 메서드):**
    1.  `@Async` 및 `@EventListener`를 사용하여 이벤트를 비동기적으로 수신한다.
    2.  `SimpMessagingTemplate` Bean을 주입받는다.
    3.  이벤트에 담긴 데이터를 바탕으로, 클라이언트에 전송할 최종 DTO를 생성한다.
    4.  `simpMessagingTemplate.convertAndSend()` 메서드를 사용하여, 해당 약속의 토픽(`/topic/plans/{planId}/live`)으로 DTO를 전송한다.

### 4.4. `LiveLocationDto` 생성

-   **목적:** WebSocket으로 전송될 데이터의 형식을 정의한다.
-   **위치:** `com.oath.domain.locationevents.dto`
-   **포함 필드:**
    -   `memberId`, `username`, `profileImageUrl`, `lat`, `lng`, `lastLiveTs` 등 `LocationUpdatedEvent`와 유사한 필드를 가진다.

## 5. (11/20) 진행 결과 업데이트

-   **결과:** 위 계획에 명시된 모든 세부 구현 계획(**`Event`, `Service 수정`, `Listener`, `DTO` 생성**)을 **성공적으로 완료함.**
-   **현재 상태:**
    -   이제 클라이언트가 위치 전송 API (`POST /api/track/batch`)를 호출하면, `TrackService`가 DB에 위치를 저장하고 `LocationUpdatedEvent`를 발행함.
    -   `LocationUpdateListener`가 이 이벤트를 받아, 해당 약속의 WebSocket 토픽 (`/topic/plans/{planId}/live`)으로 `LiveLocationDto` 형식의 위치 정보를 실시간으로 전송(Broadcast)함.
-   **다음 단계:**
    -   서버 측의 핵심 로직은 완성되었으므로, 이제 **클라이언트(Flutter)와의 실제 연동 테스트**를 통해 사용자에게 완전한 기능을 제공하는 단계로 나아가야 함. (상세 내용은 `1121_todo.md` 참고)
