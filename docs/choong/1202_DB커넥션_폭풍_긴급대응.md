### 09:20 - 근본 원인 파악 완료

#### 🔍 발견된 문제들

1. **트랜잭션 매니저 미명시**

   - 15개 Initializer 파일 중 대부분이 `@Transactional`만 사용
   - `h2TransactionManager` vs `pgTransactionManager` 혼선 가능성
   - `DataInitializer14_Review`만 `@Transactional("h2TransactionManager")` 명시

2. **중복 트랜잭션 선언**

   - 클래스 레벨: `@Transactional`
   - 메서드 레벨: `@Transactional`
   - 불필요한 중첩 트랜잭션 생성

3. **대량 개별 save() 호출 - 핵심 문제!**

   ```
   PlanScenario01_Completed.createLocationTracks():
     - for (int i = 0; i <= 10; i++) {
         locationTrackRepository.save(track);  // 11번 개별 호출
       }

   총 계산:
   - 3개 시나리오 (Completed, Ongoing, Pending)
   - 각 시나리오당 4명의 참가자
   - 각 참가자당 11개의 LocationTrack
   = 3 × 4 × 11 = 132개의 개별 save() 호출!
   ```

4. **작은 커넥션 풀**
   - PostgreSQL `maximum-pool-size: 2`
   - 132개의 동시 DB 작업에 턱없이 부족

#### 💡 해결 방안

1. 모든 Initializer에 `@Transactional("h2TransactionManager")` 명시
2. 클래스 레벨 중복 `@Transactional` 제거
3. **`locationTrackRepository.save()` → `saveAll()` 배치 저장으로 변경**
4. (선택) PostgreSQL 커넥션 풀 크기 증가 (2 → 5)
