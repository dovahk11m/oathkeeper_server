# AI서버1: 데이터 전송(Push) 구현 계획 및 결과

- **작성일:** 2025-11-20

## 1. 목표

Java 서버에서 계산된 통계 데이터를 Python AI 서버로 **전송(Push)**하는 기능의 실제 통신을 성공시키고, 데이터 전송 파이프라인이 정상적으로 동작하는지 검증한다.

## 2. 사전 문제점

-   **현상:** Java 서버에서 Python AI 서버로 API를 호출하면 `Connect timed out` 오류가 발생하며 연결에 실패했다.
-   **초기 진단:** 학원 네트워크 방화벽 또는 Python 서버의 외부 접속 설정 누락으로 추정했다.

## 3. 작업 계획 및 실행 내용

### 3.1. [1단계] 근본 원인 분석 및 규명

-   **작업 내용:**
    1.  Python 서버가 정상적으로 구동 중이며, IP 주소가 `192.168.0.3`임을 확인함.
    2.  Java 서버의 `MetricsPushService.java` 코드를 재검토함.
-   **결과:**
    -   호출 대상 URL이 실제 IP와 다른 **`http://192.168.0.187:8001/metrics/analyze`** 로 하드코딩되어 있는 것을 발견함.
    -   `Connect timed out`의 근본 원인은 네트워크 방화벽이 아닌, **단순 IP 주소 오타**였음을 최종 규명함.

### 3.2. [2단계] 코드 수정 및 설정 외부화

-   **작업 내용:**
    1.  **`application-local.yml` 수정:** AI 서버의 주소를 관리하기 위한 `ai.server.url` 변수를 추가하고, 실제 IP(`192.168.0.3`)를 설정함.
    2.  **`MetricsPushService.java` 수정:** 하드코딩된 URL을 제거하고, `@Value("${ai.server.url}")` 어노테이션을 사용하여 설정 파일의 URL 값을 주입받도록 리팩토링함.

### 3.3. [3단계] 실제 연동을 위한 리스너 복원

-   **작업 내용:**
    -   **`PlanCompletionListener.java` 수정:** 임시로 사용하던 `MockMetricsPushService` 대신, 실제 `MetricsPushService`를 사용하도록 의존성을 복원함.

## 4. 최종 검증 및 결과

-   **테스트 방법:**
    1.  Java 서버와 Python 서버를 모두 실행.
    2.  Postman을 사용하여 `planId=2`의 마지막 미도착 참가자의 도착 API (`POST /api/plans/participants/5/arrival`)를 호출하여, 플랜을 `COMPLETED` 상태로 만듦.
-   **검증 결과:**
    1.  **Java 서버 로그:** `PlanCompletionListener`가 `MetricsPushService`를 호출하고, `[metrics-push] sent memberId=...` 로그가 4명의 참가자에 대해 모두 성공적으로 출력됨을 확인.
    2.  **Python 서버 로그:** Java 서버로부터 4건의 `POST /metrics/analyze HTTP/1.1" 200 OK` 요청을 정상적으로 수신하고 처리했음을 확인.
-   **최종 결론:**
    -   Java-Python 서버 간 **데이터 전송(Push)** 통신이 성공적으로 완료되었으며, 약속 완료부터 AI 서버 데이터 전송까지 이어지는 자동화 파이프라인이 완벽하게 동작함을 입증함.
