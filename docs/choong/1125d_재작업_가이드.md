# 🚀 그룹 요약 기능 재작업 가이드

- **작성일:** 2025-11-25
- **목표:** 최근 발생한 다수의 오류(페이징, 커넥션 풀, 라우팅)를 모두 해결하고, 가장 안정적인 방식으로 그룹 요약 기능을 완성한다.

### **핵심 원칙**
1.  **한 번에 하나씩:** 여러 변경사항을 동시에 적용하지 않고, 기능 단위로 나누어 하나씩 추가하고 검증합니다.
2.  **단계별 검증:** 각 단계가 끝날 때마다 애플리케이션을 재시작하여, 문제가 없는지 반드시 확인합니다.

---

### **Phase 0: 모든 변경사항 원복 (Clean Slate)**

가장 먼저, 현재까지의 모든 변경사항을 되돌려 **"채팅방 목록이 나오지 않던 최초의 문제 상황"**으로 돌아갑니다.

1.  **작업:** Git을 사용하여 최근 수정된 모든 파일의 변경사항을 원복합니다.
    - `git checkout -- .` 또는 `git reset --hard HEAD` 등의 명령어를 사용합니다.

2.  **검증:** 애플리케이션을 재시작합니다. 앱은 정상 실행되지만, 채팅방 목록은 여전히 보이지 않는 상태여야 합니다. 이 상태가 우리의 안정적인 출발선입니다.

---

### **Phase 1: 채팅방 목록 조회 문제 해결 (안정화)**

**목표:** 다른 모든 기능을 배제하고, 오직 채팅방 목록 조회 기능만 완벽하게 수정합니다.

1.  **파일 수정 (1/2): `GroupMemberRepository.java`**
    - **경로:** `src/main/java/com/oath/domain/groups/groupRepository/GroupMemberRepository.java`
    - **내용:** `JOIN FETCH`와 `Pageable`의 충돌을 해결하고 N+1 문제를 방지하기 위해, `findByMemberIdWithGroup` 메서드를 아래와 같이 수정합니다. (메서드 이름을 `findByMemberId`로 변경)
    ```java
    // 기존의 findByMemberIdWithGroup 메서드를 아래 코드로 교체하세요.
    @Query(value = "SELECT gm FROM GroupMember gm JOIN FETCH gm.group WHERE gm.member.id = :memberId",
           countQuery = "SELECT count(gm) FROM GroupMember gm WHERE gm.member.id = :memberId")
    Page<GroupMember> findByMemberId(@Param("memberId") Long memberId, Pageable pageable);
    ```

2.  **파일 수정 (2/2): `GroupService.java`**
    - **경로:** `src/main/java/com/oath/domain/groups/groupService/GroupService.java`
    - **내용:** `getMyGroups` 메서드에서 위에서 수정한 `findByMemberId` 메서드를 호출하도록 변경합니다.
    ```java
    // getMyGroups 메서드 내부를 아래와 같이 수정하세요.
    public PageResponseDTO<GroupListResponse> getMyGroups(String email, Pageable pageable) {
        Member member = memberRepository.findByEmail(email)
                .orElseThrow(() -> new Exception404("사용자를 찾을 수 없습니다."));

        // 이 부분을 수정합니다.
        Page<GroupMember> myGroupsPage = groupMemberRepository.findByMemberId(
                member.getId(),
                pageable
        );
        // ... (이하 동일)
    }
    ```
    - **내용:** `GroupController`에서 그룹 정보를 조회할 수 있도록 `getGroupById` 메서드를 추가합니다.
    ```java
    public Group getGroupById(Long groupId) {
        return groupRepository.findById(groupId)
                .orElseThrow(() -> new Exception404("그룹을 찾을 수 없습니다."));
    }
    ```

3.  **검증:**
    - 애플리케이션을 재시작합니다.
    - **앱에 로그인하여 채팅방 목록이 정상적으로 불러와지는지 확인합니다.**
    - 이 단계가 성공하면, 우리 앱은 이제 안정적인 상태입니다.

---

### **Phase 2: 그룹 요약 기능 구현 (단계적 진행)**

이제 안정화된 앱 위에, 그룹 요약 기능을 한 단계씩 안전하게 쌓아 올립니다.

1.  **DB 필드 추가:**
    - `Group.java` 파일을 열고, `summary`, `summaryStatus`, `summaryLastUpdatedAt` 필드와 `updateSummary` 메서드를 추가합니다.
    - `SummaryStatus.java` Enum 클래스를 `com.oath.domain.groups` 패키지에 생성합니다.
    - **검증:** 앱을 재시작하여 오류 없이 실행되는지 확인합니다.

2.  **리포지토리/서비스 골격 추가:**
    - `PlanJpaRepository.java`에 `findCompletedPlanIdsByGroupId` 메서드를 추가합니다.
    - `MetricsGroupService.java`를 `com.oath.domain.groups.groupService` 패키지에 생성합니다. (단, AI 통신 로직은 "TODO" 주석만 남깁니다.)
    - `GroupController.java`에 `MetricsGroupService`를 주입하고, `getGroupMetricsSummary` 엔드포인트 메서드를 추가합니다. (마찬가지로 실제 로직은 비워둡니다.)
    - **검증:** 앱을 재시작하여 의존성 주입 오류 등이 없는지 확인합니다.

3.  **AI 통신 구현 (java.net.http.HttpClient 사용):**
    - `build.gradle`에서 `implementation 'org.springframework.boot:spring-boot-starter-webflux'` 의존성을 `implementation 'org.springframework:spring-webflux'`로 변경합니다.
    - `application-local.yml` 파일 최상단에 추가했던 `spring.main.web-application-type: servlet` 설정은 제거합니다.
    - `WebClientConfig.java`에서 Netty 관련 타임아웃 설정을 제거하고, 기본적인 `WebClient` 빈만 유지합니다. (단, `MetricsGroupService`에서는 `WebClient` 대신 `java.net.http.HttpClient`를 직접 사용합니다.)
    - `com.oath.domain.metrics.dto` 패키지에 AI 통신용 DTO 3개(`AiGroupSummaryRequest`, `AiGroupSummaryResponse`, `AiGroupSummaryStats`)를 생성합니다.
    - **검증:** 앱을 재시작하여 의존성 변경 및 설정 변경으로 인한 문제가 없는지 최종 확인합니다.

4.  **최종 로직 완성:**
    - `MetricsGroupService.java`에 `@Async`를 포함한 AI 서버 통신 로직을 `java.net.http.HttpClient`를 사용하여 완성합니다. (새로 만든 DTO 사용)
    - `GroupController.java`의 `getGroupMetricsSummary`가 `MetricsGroupService`를 호출하고, `PENDING`/`COMPLETED` 상태에 따라 다른 응답을 주도록 최종 완성합니다.
    - `com.oath.domain.groups.groupDTO` 패키지에 `GroupSummaryResponse` DTO를 생성합니다.
    - **검증:** 앱을 재시작하고, Postman 등을 이용해 `GET /api/groups/{groupId}/metrics/summary` API가 폴링 방식에 따라 정상적으로 동작하는지 테스트합니다.
