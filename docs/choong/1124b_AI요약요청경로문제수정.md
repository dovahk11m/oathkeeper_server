# 1124b - AI 요약 요청 경로 문제 해결 및 리팩토링 기록

- **작성일:** 2025-11-24
- **작업자:** 충희
- **관련 이슈:** AI 서버 연동 후, `/api/plans/{planId}/summary` API가 "생성 중" 메시지만 반환하고 실제 요약 데이터가 조회되지 않는 문제

---

## 1. 문제 현상 및 원인 분석

약속이 완료된 후 AI 요약 보고서를 요청했으나, API는 계속해서 "생성 중"이라는 응답만 반환했다.

- **Spring 서버:** `Plan.summaryStatus`가 `PROCESSING` 상태에서 멈춰있음.
- **AI(Python) 서버 로그:**
    - 초기에는 `GET /metrics/analyze/summarize/2 HTTP/1.1" 404 Not Found` 오류 발생.
    - 이후에는 `GET /metrics/report/2 HTTP/1.1" 200 OK` 로 정상 응답했으나, Spring DB에는 반영되지 않음.

**핵심 원인:**
1.  `AIService`가 AI 서버 명세와 다른 잘못된 URL(`.../analyze/summarize/{planId}`)을 호출하고 있었음.
2.  `MetricsPushService`는 요약 데이터를 받아온 후, `Plan`의 상태(`summaryStatus`)를 `COMPLETED`로 변경하는 로직이 누락되어 있었음.
3.  DB에 저장되는 요약 내용이 순수 텍스트가 아닌, AI 서버가 반환한 JSON 응답 전체였음.

---

## 2. 해결 과정

### 2.1. `AIService` 리팩토링: 잘못된 URL 호출 수정

- **문제:** `AIService`가 `ai.server.url`에 `/summarize/{planId}`를 덧붙여 직접 AI 서버에 요청하고 있었다. 이는 중복 로직이며 잘못된 경로였다.
- **해결:**
    - `AIService`에서 `RestTemplate` 직접 호출 로직을 제거.
    - 대신, 이미 AI 서버 통신 로직이 구현된 `MetricsPushService`를 주입받아 `fetchAndSaveSummary(planId)` 메소드를 호출하도록 변경.
    - 이를 통해 역할과 책임을 명확히 분리하고 코드 중복을 제거.

### 2.2. `MetricsPushService` 수정: 상태 업데이트 누락 해결

- **문제:** `fetchAndSaveSummary` 메소드가 AI 서버로부터 요약 내용을 받아와 `Plan.summary` 필드에 저장했지만, `Plan.summaryStatus`를 `COMPLETED`로 변경하지 않았다.
- **해결:** `plan.setSummary(summary)` 코드 아래에 `plan.setSummaryStatus(SummaryStatus.COMPLETED);` 라인을 추가하여 상태가 정상적으로 갱신되도록 수정.

### 2.3. `application-local.yml` 수정: 올바른 요약 데이터 요청

- **문제:** `ai.server.summary-url`이 요약 통계의 원본 JSON을 반환하는 `/metrics/report/{planId}`로 설정되어 있었다.
- **해결:**
    - AI 서버 API 명세에 따라, 최종 가공된 텍스트를 반환하는 `/metrics/report/{planId}/text`로 `summary-url`을 변경.
    - AI 서버가 별도의 컴퓨터(`192.168.0.3`)에서 실행 중인 것을 확인하고, 호스트 주소를 `localhost`에서 해당 IP로 유지.

### 2.4. `MetricsPushService` 개선: 순수 텍스트만 저장하도록 파싱 로직 추가

- **문제:** `/text` 엔드포인트의 응답은 `{"success":true, "data":"요약 텍스트..."}` 형태의 JSON이므로, 이 문자열 전체가 DB에 저장되고 있었다.
- **해결:**
    - `fetchAndSaveSummary` 메소드에서 AI 서버 응답을 받은 후, `ObjectMapper`를 사용해 JSON을 파싱.
    - `data` 필드에 담긴 순수한 텍스트 값만 추출하여 `plan.setSummary()`에 전달하도록 수정.

---

## 3. 최종 결과

위의 수정들을 통해, `/api/plans/{planId}/summary` API 호출 시 다음과 같이 정상 동작함을 확인했다.

1.  최초 호출 시 "생성 중" 메시지 반환.
2.  백그라운드에서 비동기 요약 생성 작업 수행.
3.  잠시 후 재호출 시, `Plan.summary` 필드에 저장된 **순수 한글 요약 텍스트**가 정상적으로 조회됨.

AI 서버 연동 관련 트러블슈팅을 완료하고, 관련 코드의 안정성과 명확성을 개선했다.

---

## 4. 추가 트러블슈팅: 샘플 데이터 문제 해결

### 4.1. 문제 현상: `planId=1` 요약 요청 시 `409 Conflict` 발생

- 테스트 중, `planId=1`에 대한 요약 요청 시 AI 서버가 `409 Conflict`를 반복적으로 반환하는 문제를 발견.
- **원인:** AI 서버의 `409` 코드는 "요약을 생성하기 위한 데이터가 부족하다"는 의미의 정상 응답. 근본 원인은 Spring의 `DataInitializer12_Plan`에서 `planId=1`을 처음부터 `Status.COMPLETED`로 생성하여, 통계 계산(`Rollup`) 및 AI 서버 전송(`Push`) 로직이 트리거되지 않았기 때문.

### 4.2. 해결 과정: `DataInitializer` 보강

- **문제:** `DataInitializer`는 상태 변경 이벤트를 발생시키지 않으므로, `planId=1`에 대한 통계 데이터가 AI 서버에 전달되지 않았다.
- **해결:**
    - `DataInitializer12_Plan.java`에 `MetricsRollupService`와 `MetricsPushService`를 주입.
    - '완료된 약속'(`planId=1`) 데이터 생성 로직 마지막에, `rollupService.rebuildForPlan()`과 `pushService.pushPlan()`을 **수동으로 호출**하는 코드를 추가.
    - 이를 통해 애플리케이션 시작 시점에 `planId=1`에 대한 통계 데이터가 AI 서버에 미리 준비되도록 수정.

### 4.3. 최종 결과

- 수정 후 애플리케이션을 재시작하자, `planId=1`에 대한 요약 요청도 정상적으로 처리됨을 확인.
- 테스트 데이터의 불완전성으로 인한 문제를 해결하고, 향후 테스트의 신뢰도를 높임.
