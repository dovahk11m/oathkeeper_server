# AI 서버 연결 실패 해프닝 회고 (구 '학원컴 환경 대응 전략')

- **최초작성:** 2025-11-18
- **최종수정:** 2025-11-20

---

## 1. 문제 현상

-   **현상:** Java 서버에서 Python AI 서버로 API를 호출하면, `Connect timed out` 오류가 발생하며 통신에 실패함.
-   **특이점:** 과거 다른 담당자가 플러터 클라이언트에서 동일한 Python 서버로 연결했을 때는 성공했었음.

## 2. 초기 분석 및 잘못된 접근

-   **초기 가설:** 학원 네트워크의 복잡한 방화벽 정책이나, Python 서버의 외부 접속 허용 설정(`--host 0.0.0.0`) 누락 등 **환경적인 문제**일 것으로 추측함.
-   **잘못된 대응:**
    -   실제 통신을 포기하고, `MockMetricsPushService`를 만들어 API 연동을 시뮬레이션하는 방향으로 우회함.
    -   네트워크 문제 해결을 위해 다른 담당자에게 작업을 인수인계하려고 함.

## 3. 진짜 원인: 단순 IP 주소 하드코딩 오류

-   **원인:** 인수인계 문서를 작성하던 중, `MetricsPushService.java` 코드에 하드코딩된 AI 서버의 IP 주소가 **`192.168.0.187`** 로 잘못 기입되어 있는 것을 발견함.
-   **실제 IP:** 당시 구동 중이던 Python 서버의 실제 IP는 **`192.168.0.3`** 이었음.
-   **결론:** Java 서버는 존재하지 않는 엉뚱한 IP 주소로 계속 연결을 시도했기 때문에, 응답이 없어 `Connect timed out`이 발생하는 것은 당연한 결과였음.

## 4. 해결 조치

1.  **설정 외부화:** 하드코딩된 IP 주소를 `application-local.yml` 파일에 `ai.server.url` 변수로 추출하여 실수를 방지하고 유연성을 확보함.
2.  **실제 연동 테스트:** `PlanCompletionListener`가 `Mock...Service` 대신 실제 `MetricsPushService`를 호출하도록 코드를 복원하고, 성공적으로 통신이 이루어짐을 확인함.

## 5. 교훈 및 재발 방지 대책

-   **교훈 1: 가장 기본적인 것을 먼저 의심하자.**
    -   복잡한 네트워크 환경이나 방화벽 문제를 추측하기 전에, IP 주소, 포트 번호, 엔드포인트 경로 등 가장 기본적인 설정값이 정확한지부터 여러 번 확인해야 한다.
-   **교훈 2: 매직 넘버와 하드코딩을 피하자.**
    -   IP 주소, API 키 등 외부 환경에 따라 변할 수 있는 값들은 반드시 설정 파일(`.yml`, `.properties`)로 분리하여 관리한다. 이는 실수를 줄이고, 환경 변경에 유연하게 대처할 수 있게 한다.
-   **교훈 3: "안된다"고 결론 내리기 전에, 직접 확인하자.**
    -   "방화벽 때문에 안될 것이다"라고 지레짐작하고 우회하는 대신, Postman 등을 이용해 가장 단순한 형태로 직접 통신을 시도해봤다면 문제를 더 빨리 발견했을 것이다.
