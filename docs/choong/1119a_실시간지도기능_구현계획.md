# 1118d 실시간 지도 기능 구현 계획

## 1. 목표

클라이언트로부터 수신하여 DB에 저장된 사용자의 실시간 위치(`LocationTrack`) 정보를, WebSocket을 통해 해당 약속의 구독자들에게 실시간으로 전송(Broadcast)하는 기능을 구현한다.

## 2. 현재 상태 및 문제점

-   **데이터 수집 (`locationevents`):** 클라이언트의 위치 정보를 받아 `LocationTrack` 엔티티로 DB에 저장하는 기능은 구현되어 있음.
-   **실시간 통신 통로 (`LiveMapSocketConfig`):** WebSocket 연결을 위한 엔드포인트(`/ws-livemap`)와 토픽(`/topic/plans/{planId}/live`)은 준비되어 있음.
-   **문제점:** 데이터 수집과 통신 통로 사이를 이어주는 **연결고리가 없음.** 즉, DB에 위치가 저장되어도, 이 정보가 WebSocket 구독자에게 자동으로 전송되지 않음.

## 3. 해결 전략: 이벤트 기반 아키텍처 도입

`TrackService`가 `LocationTrack`을 저장하는 시점에 이벤트를 발생시키고, 별도의 리스너가 이 이벤트를 받아 WebSocket으로 메시지를 전송하도록 역할을 분리한다.

## 4. 세부 구현 계획

### 4.1. `LocationUpdatedEvent` 생성

-   **목적:** 새로 업데이트된 위치 정보를 담는 이벤트 객체를 정의한다.
-   **위치:** `com.oath.domain.locationevents.event` 패키지를 생성하고, 그 안에 클래스를 만든다.
-   **포함 데이터:**
    -   `Long planId`: 어떤 약속에 대한 위치 정보인지 식별
    -   `Long memberId`: 누가 보낸 위치 정보인지 식별
    -   `String username`: 사용자의 이름
    -   `String profileImageUrl`: 사용자의 프로필 이미지 URL
    -   `Double lat`: 위도
    -   `Double lng`: 경도
    -   `LocalDateTime lastLiveTs`: 위치 정보가 기록된 시간

### 4.2. `TrackService` 수정

-   **목적:** 위치 정보를 DB에 저장한 직후, 위에서 정의한 `LocationUpdatedEvent`를 발행(publish)한다.
-   **수정 대상:** `TrackService.ingestTracks` (또는 유사한 이름의 메서드)
-   **추가 로직:**
    -   `LocationTrack` 저장 후, 해당 정보를 바탕으로 `LocationUpdatedEvent` 객체를 생성한다.
    -   Spring의 `ApplicationEventPublisher`를 사용하여 이벤트를 발행한다.

### 4.3. `LocationUpdateListener` 생성

-   **목적:** `LocationUpdatedEvent`를 수신하여, 최종 데이터를 가공하고 WebSocket으로 전송한다.
-   **위치:** `com.oath.domain.locationevents.event.listener` 패키지를 생성하고, 그 안에 클래스를 만든다.
-   **주요 로직 (`handleLocationUpdate` 메서드):**
    1.  `@TransactionalEventListener`를 사용하여 이벤트를 수신한다.
    2.  `SimpMessagingTemplate` Bean을 주입받는다.
    3.  이벤트에 담긴 데이터를 바탕으로, 클라이언트에 전송할 최종 DTO를 생성한다.
    4.  `simpMessagingTemplate.convertAndSend()` 메서드를 사용하여, 해당 약속의 토픽(`/topic/plans/{planId}/live`)으로 DTO를 전송한다.

### 4.4. 실시간 위치 전송 DTO 생성

-   **목적:** WebSocket으로 전송될 데이터의 형식을 정의한다.
-   **위치:** `com.oath.domain.locationevents.dto.LiveLocationDto`
-   **포함 필드:**
    -   `memberId`, `username`, `profileImageUrl`, `lat`, `lng`, `lastLiveTs` 등 `LocationUpdatedEvent`와 유사한 필드를 가진다.

## 5. 테스트 및 검증

1.  두 명의 사용자가 같은 약속(`planId`)에 참여.
2.  사용자 A가 WebSocket 클라이언트로 `/topic/plans/{planId}/live`를 구독.
3.  사용자 B가 위치 전송 API (`/api/track/batch`)를 호출.
4.  서버 로그에 `LocationUpdateListener`가 이벤트를 수신하고 메시지를 전송하는 로그가 출력되는지 확인.
5.  사용자 A의 WebSocket 클라이언트가 사용자 B의 위치 정보가 담긴 메시지를 수신하는지 확인.
