# 1125(b) 작업 계획: AI 서버 API v2 연동

- **작성일:** 2025-11-25
- **주요 목표:** Python AI 서버의 신규 API(v2) 명세에 맞춰, Spring 서버의 그룹 요약 기능 관련 코드를 리팩토링하고 안정적으로 연동한다.
- **참조 문서:** `docs/1125_API_v2_구현완료_회신.md`

---

## 1. 배경

- Python AI 서버 팀에서 그룹 통계/요약 API를 v2 스펙으로 업데이트하고 회신함.
- 기존에 2개로 분리되어 있던 API가 **1개의 통합 API**로 변경되었으며, 요청/응답 DTO 구조 또한 변경됨.
- 현재 Spring 서버의 관련 로직은 v1 스펙을 기준으로 구현되어 있어, v2 스펙에 맞춘 코드 수정이 반드시 필요함.

## 2. 세부 작업 계획 (TODO)

### 2.1. DTO 리팩토링 (AI 서버 통신용)

- **목표:** AI 서버 v2의 JSON 구조에 정확히 매핑되는 DTO 클래스를 재구성한다.
- **세부 과업:**
    - [ ] **AI 서버 응답 DTO 생성/수정:**
        - `GroupSummaryResponse`, `GroupSummaryData`, `GroupSummaryStats` 등 회신 문서 가이드에 명시된 DTO 클래스를 `com.oath.domain.metrics.dto` 패키지 내에 생성하거나 수정한다.
        - `@JsonProperty` 어노테이션을 사용하여 JSON의 `snake_case` 필드명과 Java의 `camelCase` 필드명을 정확히 매핑한다.
    - [ ] **AI 서버 요청 DTO 수정:**
        - `style`, `notes`, `mode` 필드를 포함하도록 요청 DTO를 수정한다. (현재는 `Map`으로 되어 있어, 별도 DTO로 관리하는 것을 고려)

### 2.2. 서비스 로직 수정 (`MetricsGroupService`)

- **목표:** AI 서버 호출 로직을 v2 스펙에 맞게 변경하고, 비동기 처리를 안정적으로 유지한다.
- **세부 과업:**
    - [ ] **`requestGroupSummaryAnalysis` 메서드 수정:**
        - `aiWebClient` 호출 시, v2 스펙에 맞는 요청 DTO를 생성하여 `bodyValue`에 담도록 수정한다.
        - `mode` 파라미터 사용 전략을 결정하고 적용한다. (예: 비동기 백그라운드 작업이므로 `"llm"` 모드를 기본으로 사용)
        - `bodyToMono`의 타입을 기존 `Object.class`에서 새로 만든 v2 응답 DTO 클래스로 변경하여 타입 안정성을 확보한다.
    - [ ] **응답 데이터 처리 로직 수정:**
        - v2 응답 DTO 구조에 맞게 `text_summary` 값을 정확히 추출하여 `Group` 엔티티의 `summary` 필드에 저장하도록 수정한다. (`response.getData().getTextSummary()`)
    - [ ] **에러 및 경고 처리:**
        - AI 서버 응답에 `warnings` 필드가 있을 경우, 이를 로그에 기록하는 로직을 추가한다.

### 2.3. 네트워크 설정 검토

- **목표:** AI 서버의 `llm` 모드가 최대 30초 이상 소요될 수 있음을 고려하여, 통신 타임아웃 설정을 확인하고 조정한다.
- **세부 과업:**
    - [ ] `WebClient` 또는 `RestTemplate`이 생성되는 설정 파일(`WebClientConfig` 등)을 찾는다.
    - [ ] `read-timeout` 값을 최소 **35초** 이상으로 넉넉하게 설정하여, LLM의 긴 응답 시간 동안 연결이 끊어지지 않도록 보장한다.

### 2.4. 테스트 및 검증

- **목표:** 변경된 로직이 실제 환경에서 정상적으로 동작하는지 검증한다.
- **세부 과업:**
    - [ ] 로컬 환경에서 그룹 요약 API(`GET /api/groups/{groupId}/metrics/summary`)를 호출하여, `PENDING` -> `COMPLETED` 상태 변경 및 `summary` 필드 업데이트가 정상적으로 이루어지는지 확인한다.
    - [ ] `application-local.log` 파일을 확인하여, AI 서버 요청/응답 및 에러/경고 로그가 올바르게 기록되는지 검증한다.
