# 1118a 그룹 통계 누적 기능 구현 계획

## 1. 목표

'플랜 완료' 시점에서, 완료된 `Plan`의 통계 데이터를 해당 `Plan`이 소속된 `Group`의 전체 통계에 합산(누적)하는 기능을 구현한다.

## 2. 구현 절차

### 2.1. `Group` 엔티티 캡슐화 강화

- **파일:** `Group.java`
- **내용:**
    - 현재 `Group` 엔티티의 통계 관련 필드들은 외부에서 직접 수정 가능한 상태일 가능성이 높다.
    - `Plan` 엔티티를 리팩토링했던 것과 같이, `@Setter`를 제거하고 통계를 안전하게 업데이트할 수 있는 명시적인 비즈니스 메서드를 추가한다.
    - **예시:** `public void addPlanStatistics(Plan completedPlan)`
        - 이 메서드는 `Plan` 객체를 인자로 받아, 해당 플랜의 통계치를 그룹의 통계치에 누적한다.

### 2.2. `MetricsRollupService`에 누적 로직 추가

- **파일:** `MetricsRollupService.java`
- **내용:**
    - 그룹 통계를 누적하는 새로운 `public` 메서드를 생성한다.
    - **메서드명:** `public void accumulatePlanStatsToGroup(Long planId)`
    - **내부 로직:**
        1. `planId`로 `Plan` 엔티티를 조회한다.
        2. `plan.getGroup()`을 통해 연결된 `Group` 엔티티를 조회한다.
        3. 만약 `Group`이 존재하지 않으면, 로그를 남기고 조용히 로직을 종료한다. (오류를 발생시키지 않음)
        4. `Group`이 존재하면, 1번 단계에서 만든 `group.addPlanStatistics(plan)` 메서드를 호출하여 통계를 누적시킨다.
        5. 변경된 `Group` 엔티티는 Dirty-checking에 의해 트랜잭션 커밋 시점에 자동으로 업데이트되므로, 별도의 `save` 호출은 필요 없다.

### 2.3. `PlanCompletionListener`에서 서비스 호출

- **파일:** `PlanCompletionListener.java`
- **내용:**
    - `PlanCompletedEvent`를 처리하는 `handlePlanCompletedEvent` 메서드 내부에 다음 코드를 추가한다.
    - `rollupService.aggregateMetricsForPlan(planId)` 호출이 성공적으로 끝난 바로 다음에 `rollupService.accumulatePlanStatsToGroup(planId)`를 호출한다.
    - 이를 통해 플랜 자체의 통계 집계가 완료된 후, 그룹 통계 누적이 순차적으로 이루어지도록 보장한다.

## 3. 예상 결과

- 플랜이 `COMPLETED` 상태로 변경될 때마다, 해당 플랜이 속한 그룹의 통계 필드(`total_late_minutes`, `total_on_time_arrivals` 등)가 플랜의 통계만큼 자동으로 증가한다.
- 이를 통해 그룹별 활동에 대한 누적 데이터를 지속적으로 관리할 수 있게 된다.
