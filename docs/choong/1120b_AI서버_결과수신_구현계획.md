# 1120b AI 서버 결과 수신 구현 계획

- **작성일:** 2025-11-20

## 1. 목표

Java 서버가 Python AI 서버로 통계 데이터를 전송(Push)한 후, 일정 시간 뒤 AI 서버로부터 분석이 완료된 '요약 보고서'를 다시 수신(Fetch)하여 `Plan` 엔티티에 저장하는 기능을 구현한다.

## 2. 선행 조건

- `1120a` 계획에 따라, `PlanCompletionListener`에서 `MetricsPushService`를 호출하여 AI 서버로 데이터를 전송하는 기능이 정상적으로 동작해야 한다.

## 3. 구현 계획

### 3.1. `Plan` 엔티티에 요약 필드 추가

-   **파일:** `Plan.java`
-   **작업:** AI가 생성한 텍스트 요약 보고서를 저장할 수 있는 `summary` 필드를 추가한다.
    ```java
    @Column(columnDefinition = "TEXT")
    private String summary;
    ```
-   해당 필드를 업데이트할 수 있는 setter 또는 비즈니스 메서드를 추가한다.

### 3.2. `application-local.yml`에 요약 API URL 변수 추가

-   **파일:** `application-local.yml`
-   **작업:** 하드코딩을 피하기 위해, AI 서버의 요약 보고서 요청 URL을 `ai.server` 섹션에 변수로 추가한다.
    ```yaml
    ai:
      server:
        url: "http://192.168.0.3:8001/metrics/analyze"
        summary-url: "http://192.168.0.3:8001/metrics/report/{planId}" # 예시
    ```
-   **참고:** `{planId}` 부분은 `RestTemplate`에서 동적으로 치환될 부분이므로 그대로 둔다.

### 3.3. `MetricsPushService`에 요약 보고서 수신 메서드 추가

-   **파일:** `MetricsPushService.java`
-   **작업:** `fetchAndSaveSummary(Long planId)` 라는 새로운 `public` 메서드를 생성한다.
-   **내부 로직:**
    1.  `@Value`를 사용하여 `ai.server.summary-url` 값을 주입받는다.
    2.  `RestTemplate`을 사용하여, 주입받은 URL의 `{planId}`를 실제 `planId`로 치환하여 `GET` 요청을 보낸다.
    3.  AI 서버로부터 받은 텍스트(요약 보고서) 응답을 파싱한다.
    4.  `planJpaRepository`를 사용하여 `planId`로 `Plan` 엔티티를 조회한다.
    5.  조회한 `Plan` 엔티티의 `summary` 필드에 받아온 텍스트를 저장한다. (`plan.setSummary(...)`)

### 3.4. `PlanCompletionListener`에서 새 메서드 호출

-   **파일:** `PlanCompletionListener.java`
-   **작업:** `pushService.pushPlan(planId)` 호출 다음에, 새로 만든 `pushService.fetchAndSaveSummary(planId)`를 호출하는 코드를 추가한다.
-   **고려사항 (AI 처리 시간):**
    -   `pushPlan` 직후에 바로 `fetch`를 호출하면, AI 서버가 아직 분석을 완료하지 못했을 수 있다.
    -   **초기 구현:** 일단 `Thread.sleep(5000);` (5초 대기)와 같은 간단한 지연 로직을 추가하여 테스트한다.
    -   **향후 개선:** 더 정교한 방법으로, AI 서버가 분석 완료 후 Java 서버로 콜백(Callback)을 보내거나, 상태를 조회하는 API를 주기적으로 호출하는 방식 등을 고려할 수 있다.

## 4. 테스트 및 검증

1.  Java 서버와 Python 서버를 모두 실행한다.
2.  Postman을 사용하여 플랜을 `COMPLETED` 상태로 만든다.
3.  서버 로그에서 `PlanCompletionListener`가 `pushPlan`과 `fetchAndSaveSummary`를 순차적으로 호출하는지 확인한다.
4.  H2 콘솔에 접속하여 `SELECT SUMMARY FROM PLAN_TB WHERE ID = {planId};` 쿼리를 실행하고, `SUMMARY` 컬럼에 AI가 생성한 텍스트가 정상적으로 저장되었는지 확인한다.
