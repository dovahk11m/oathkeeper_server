2.  **API 문서 표준화 및 최신화 (한영님 지원):**

    -   **역할:**
        -   우리가 정립한 문서화 규칙(응답 예시 포함 등)을 다른 API 문서들에도 일관되게 적용.
        -   팀원들이 각자 맡은 기능의 API를 문서화할 때, 가이드를 제공하고 리뷰를 통해 품질을 유지.

3.  **샘플 데이터 중앙 관리:**

## 3. 내일 작업 사전 브리핑: 실시간 지도 기능

- **상황:** "실시간 지도 기능"의 서버 측 핵심 로직(위치 수신 → 이벤트 발행 → WebSocket으로 전송)은 **이미 구현이 완료된 상태**이다. (`locationevents` 패키지 참고)
- **문제:** 회의록에 따르면, 클라이언트 측의 **화면과 로직이 대부분 미구현 상태**이다.
- **다음 목표:** 새로운 서버 기능을 만드는 것이 아니라, **이미 구현된 서버 기능을 클라이언트와 성공적으로 연동하여 사용자에게 완전한 기능을 제공**하는 것이다.

### 3.1. 연동을 위한 체크리스트

내일 '실시간 지도 기능' 작업을 시작할 때, 아래 항목들을 클라이언트 개발자(성빈님)와 함께 논의하고 진행해야 한다.

1.  **API 및 WebSocket 명세 공유:**
    -   **위치 전송 API:** `POST /api/track/batch`
    -   **WebSocket 엔드포인트:** `/ws-livemap`
    -   **구독 토픽(Topic):** `/topic/plans/{planId}/live`
    -   **전송 데이터 형식(DTO):** `LiveLocationDto` (`memberId`, `username`, `lat`, `lng` 등 포함)
    -   위 명세들을 담은 `LIVE_MAP_API.md` 문서를 작성하여 공유한다.

2.  **클라이언트 구현 상태 확인:**
    -   `pubspec.yaml`을 통해 `stomp_dart_client`, `flutter_naver_map`, `geolocator` 등 필요한 라이브러리가 모두 준비되어 있는지 다시 확인한다.
    -   클라이언트가 주기적으로 자신의 위치를 서버로 전송하는 기능(GPS -> API 호출)이 구현되어 있는지 확인한다.
    -   클라이언트가 특정 약속의 WebSocket 토픽을 구독하는 기능이 구현되어 있는지 확인한다.

3.  **통합 테스트 및 디버깅:**
    -   두 명의 사용자가 같은 약속에 참여한 상황을 가정하고 테스트를 진행한다.
    -   **사용자 A**가 위치를 변경하면, **사용자 B**의 지도 화면에 있는 사용자 A의 마커가 실시간으로 움직이는지 확인한다.
    -   만약 동작하지 않는다면, 서버 로그와 클라이언트 로그를 함께 보며 어느 단계(위치 전송, 서버 처리, WebSocket 메시지 수신, 지도 UI 업데이트)에서 문제가 발생하는지 디버깅한다.
