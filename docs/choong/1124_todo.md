## 3. 금일 작업 결산 (2025-11-24)

### 3.1. AI 요약 기능 안정화 및 트러블슈팅
- **개요**: AI 서버 연동 후, 요약 API가 "생성 중" 메시지만 반환하고 실제 데이터가 조회되지 않는 문제를 해결하고, 관련 테스트 데이터 및 문서를 보강했다.
- **주요 해결 내용**:
    1.  **잘못된 URL 호출 수정**: `AIService`가 잘못된 경로(`.../summarize/{id}`)를 호출하던 문제를 `MetricsPushService`를 사용하도록 리팩토링하여 해결.
    2.  **상태 업데이트 누락 해결**: `MetricsPushService`에서 요약 생성 후 `Plan.summaryStatus`를 `COMPLETED`로 변경하는 로직을 추가.
    3.  **응답 데이터 파싱**: AI 서버의 JSON 응답에서 순수 텍스트만 추출하여 DB에 저장하도록 `ObjectMapper`를 사용한 파싱 로직 추가.
    4.  **샘플 데이터 보강**: `DataInitializer12_Plan`에서 `planId=1`의 통계 데이터가 생성되지 않아 발생하던 `409 Conflict` 오류를, 데이터 생성 후 통계 롤업 및 푸시 서비스를 수동 호출하도록 수정하여 해결.
- **산출물**:
    - `docs/choong/1124b_AI요약요청경로문제수정.md`: 트러블슈팅 과정 기록.

### 3.2. 그룹 내 약속 목록 조회 기능 구현
- **개요**: 채팅방(그룹)에 여러 약속이 누적될 경우, 사용자가 특정 약속의 요약을 선택해서 볼 수 없는 아키텍처 문제를 해결하기 위한 기반 API를 구현했다.
- **주요 구현 내용**:
    1.  **`GET /api/groups/{groupId}/plans` API 신규 구현**:
        - 특정 그룹에 속한 약속 목록을 상태별, 날짜순으로 페이징하여 조회하는 기능을 구현.
        - `PlanJpaRepository`, `PlanCoreService`, `PlanFacade`, `GroupController` 등 전 계층에 걸쳐 필요한 로직 및 DTO(`SimplePlan`) 추가.
    2.  **코드 개선**:
        - `PlanJpaRepository`의 JPQL 쿼리에서 `status`가 `null`일 때도 동작하도록 수정하고, 중복 `ORDER BY` 절을 제거.
        - `GroupController`의 예외 처리 방식을 `orElseThrow(() -> new Exception404(...))`로 통일하여 코드 일관성 확보.
- **산출물**:
    - `docs/GROUP_API.md`: 신규 API 명세 및 클라이언트 구현 시나리오 업데이트.
    - `docs/PYTHON_API_REQ.md`: 향후 필요한 '그룹 누적 통계' 기능에 대한 Python 서버 신규 API 요청서 작성.
