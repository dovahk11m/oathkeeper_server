# 1125g_그룹AI요청실패원인분석

- **작성일:** 2025-11-25
- **문제:** 그룹 요약 기능이 정상적으로 동작하지 않음 (AI 서버로부터 요약이 도착하지 않음).
- **관련 기능:** `GET /api/groups/{groupId}/metrics/summary` 엔드포인트 및 `MetricsGroupService`의 AI 서버 연동 로직.

---

## 1. 문제 현상 요약

개별 약속(Plan)에 대한 요약은 정상적으로 처리되고 DB에 저장되는 것이 로그를 통해 확인되나, 그룹(Group)에 대한 AI 요약은 요청 후에도 DB에 반영되지 않거나, 관련 로그가 출력되지 않고 있습니다.

**관찰된 증상:**
- `Group` 엔티티의 `summaryStatus` 필드가 `null`로 유지됨.
- `GroupController.getGroupMetricsSummary` 메서드 내 `metricsGroupService.requestGroupSummary` 호출 직전의 디버그 로그(`Calling MetricsGroupService.requestGroupSummary for groupId: {}`)가 출력되지 않음.
- `MetricsGroupService` 내부의 AI 서버 요청/응답 관련 디버그 로그도 출력되지 않음.

---

## 2. 최근 디버깅 및 변경 사항

문제 해결을 위해 다음과 같은 변경 및 디버깅 단계를 거쳤습니다.

1.  **`AiGroupSummaryResponse.java` DTO 수정:** AI 서버 응답 스펙에 맞춰 `success`, `message`, `warnings` 필드 추가.
2.  **`application-local.yml` 로그 레벨 조정:** `com.oath: debug` 설정 추가하여 상세 로그 활성화.
3.  **`MetricsGroupService.java` 로직 보강:**
    *   AI 서버 요청/응답 본문 상세 로깅 추가.
    *   요약할 `completedPlanIds`가 없는 경우 `FAILED` 처리 로직 추가.
    *   AI 응답 `success: false` 및 HTTP 409 Conflict 처리 로직 추가.
    *   다양한 예외 발생 시 `FAILED` 상태로 업데이트하도록 예외 처리 강화.
    *   `ai.server.url`을 AI 서버의 기본 URL(`http://192.168.0.3:8001`)로 수정.
    *   AI 서버 요청 URI를 `/metrics/group/summary`로 수정.
4.  **`GroupController.java` 디버그 로그 추가:** `getGroupMetricsSummary` 메서드 내 `metricsGroupService.requestGroupSummary` 호출 직전에 디버그 로그 추가.
5.  **`DataInitializer12_Plan.java` 수정:**
    *   샘플 그룹(`sampleGroup`)에 대해 `metricsGroupService.requestGroupSummary`를 명시적으로 호출하도록 추가.
    *   그룹의 `summaryStatus`를 `null`로 초기화하는 로직 추가 (기본값이 `null`이므로 선택 사항).

---

## 3. 잠재적 원인 (가설)

현재까지의 관찰 및 변경 사항을 바탕으로 그룹 요약 요청이 실패하는 잠재적 원인은 다음과 같습니다.

### 가설 1: `GroupController.getGroupMetricsSummary` 엔드포인트가 호출되지 않음.
- **설명:** 클라이언트(Postman, Swagger UI 등)에서 `GET /api/groups/{groupId}/metrics/summary` 엔드포인트를 실제로 호출하지 않았을 가능성.
- **근거:** `GroupController` 내부에 추가한 디버그 로그가 전혀 출력되지 않음.

### 가설 2: `GroupController`의 로직이 `MetricsGroupService` 호출 조건을 만족하지 못함.
- **설명:** `getGroupMetricsSummary` 메서드는 `group.getSummaryStatus()`가 `COMPLETED`나 `PENDING`이 아닐 때만 `metricsGroupService.requestGroupSummary`를 호출합니다. `DataInitializer`에서 `summaryStatus`를 `null`로 초기화했음에도 불구하고, 어떤 이유로 인해 이 조건이 충족되지 않을 수 있습니다.
- **근거:** `group.getSummaryStatus()`가 `null`이라는 DB 조회 결과가 있었으나, 컨트롤러가 이 값을 정확히 읽고 있는지 확인 필요.

### 가설 3: `DataInitializer12_Plan` 내의 `MetricsGroupService` 호출 문제.
- **설명:** `DataInitializer`에서 `metricsGroupService.requestGroupSummary(sampleGroup.getId())`를 호출했지만, 이 호출이 비동기(`@Async`)로 동작하면서 초기화 트랜잭션과 충돌하거나, 애플리케이션 컨텍스트가 완전히 로드되지 않은 시점에 호출되어 문제가 발생할 수 있습니다.
- **근거:** `DataInitializer`는 애플리케이션 시작 시점에 실행되므로, `@Async` 메서드의 트랜잭션 경계나 스레드 컨텍스트 문제가 발생할 가능성.

### 가설 4: AI 서버 자체의 문제 또는 네트워크 연결 문제.
- **설명:** Spring 애플리케이션에서 AI 서버로의 네트워크 연결이 실패했거나, AI 서버가 요청을 받지 못했거나, AI 서버에서 내부 오류가 발생했을 수 있습니다.
- **근거:** `MetricsGroupService` 내부의 AI 서버 요청/응답 디버그 로그가 출력되지 않으므로, 호출 시도조차 되지 않았거나, 호출 직후 예외가 발생했을 가능성.

### 가설 5: `completedPlanIds`가 비어있음.
- **설명:** `MetricsGroupService`에 `completedPlanIds`가 비어있을 경우 AI 서버 요청을 보내지 않고 `FAILED` 처리하는 로직을 추가했습니다. `DataInitializer`에서 생성된 `sampleGroup`에 연결된 완료된 약속이 실제로 없는 경우 이 로직에 의해 요청이 중단될 수 있습니다.
- **근거:** `DataInitializer`에서 `plan1`을 `COMPLETED` 상태로 생성했지만, 해당 약속이 `sampleGroup`에 올바르게 연결되었는지, 그리고 `planJpaRepository.findCompletedPlanIdsByGroupId(groupId)`가 올바른 `planId`를 반환하는지 확인 필요.

## 4. 다음 조사 단계

위 가설들을 검증하기 위해 다음 단계를 진행해야 합니다.

1.  **`GET /api/groups/{groupId}/metrics/summary` 엔드포인트 수동 호출 및 로그 확인:**
    *   Postman이나 Swagger UI를 사용하여 `groupId=1` (샘플 그룹 ID)으로 `GET /api/groups/1/metrics/summary`를 직접 호출합니다.
    *   이때 Spring 애플리케이션의 모든 로그를 면밀히 관찰하여, `GroupController`의 디버그 로그(`Calling MetricsGroupService...`)와 `MetricsGroupService` 내부의 AI 서버 요청/응답 디버그 로그가 출력되는지 확인합니다.
    *   **가장 중요한 단계입니다.** 이 로그들을 통해 어디까지 실행되는지 파악할 수 있습니다.

2.  **DB에서 `Group` 엔티티 상태 직접 확인:**
    *   애플리케이션 실행 후, H2 콘솔 등을 통해 `group_tb` 테이블에서 `id=1`인 그룹의 `summary`, `summary_status`, `summary_last_updated_at` 필드 값을 직접 확인합니다.

3.  **AI 서버 로그 확인 (가능하다면):**
    *   Python AI 서버가 실행 중이라면, 해당 서버의 로그를 확인하여 Spring 애플리케이션으로부터 요청이 도착했는지, 어떤 응답을 보냈는지 확인합니다.

4.  **디버거를 이용한 단계별 실행:**
    *   위 로그 확인으로도 문제가 파악되지 않는다면, IDE의 디버거를 사용하여 `GroupController.getGroupMetricsSummary` 메서드와 `MetricsGroupService.requestGroupSummary` 메서드를 단계별로 실행하며 변수 값과 실행 흐름을 추적합니다.

이 단계를 통해 문제의 정확한 원인을 파악할 수 있을 것입니다.
