# 1117_AI 연동 환경 제약 대응 전략

이 문서는 현재 개발 환경(학원 컴퓨터)의 네트워크 보안 정책으로 인해 Python AI 서버와의 직접적인 통신 테스트가 어려운 상황에 대한 판단과, 이에 대한 대응 전략을 정의합니다.

---

### 1. 문제 상황 요약

- **현상**: Java Spring Boot 서버에서 Python AI 서버(`http://192.168.0.187:8001`)로의 HTTP 통신 시, `Connection refused` 오류가 지속적으로 발생.
- **분석 결과**:
    - `MetricsRollupService`를 통한 Java 서버 내부의 데이터 집계 로직은 정상 동작 확인.
    - Python AI 서버 자체는 `0.0.0.0:8001`에서 정상 실행 중이며, 웹 브라우저나 Flutter 앱(안드로이드 에뮬레이터)을 통한 접근은 성공했었음.
    - Java 서버가 `www.google.com`과 같은 외부 인터넷 연결은 성공했으나, `192.168.0.187:8001` (자기 자신의 IP 주소)로의 연결은 실패.
- **결론**: 학원 컴퓨터의 강력한 네트워크 보안 정책(방화벽, 루프백 차단 등)으로 인해, Java 프로세스가 자기 자신(호스트 PC)의 특정 포트로 연결하는 것이 차단되고 있음. 이는 코드의 문제가 아닌, 개발 환경의 제약 사항임.

---

### 2. 대응 전략

AI 서버와의 직접적인 통신 테스트는 현재 환경에서 불가능하므로, 개발의 연속성을 위해 다음과 같은 전략을 채택합니다.

#### **1) Java 서버 내부 로직 개발 및 테스트 집중**

- **목표**: AI 서버와의 통신을 제외한, Java 서버의 모든 내부 비즈니스 로직(데이터 집계, 통계 계산, 그룹 스탯 누적 등)을 완벽하게 구현하고 테스트합니다.
- **수행 내용**:
    - `MetricsOrchestrationController.java`에서 `MetricsPushService` 호출 및 `aiClient`를 통한 결과 수신 로직을 **임시로 주석 처리**하여 `Connection refused` 오류가 발생하지 않도록 합니다.
    - `MetricsRollupService`를 통해 `ParticipantMetrics`가 정상적으로 생성되는지 확인하고, 이후 구현될 그룹 스탯 누적 로직 등을 철저히 검증합니다.
- **의의**: AI 서버와의 연동이 불가능하더라도, Java 서버의 핵심 기능은 문제없이 개발하고 완성도를 높일 수 있습니다.

#### **2) Flutter 앱을 통한 AI 서버 기능 테스트 병행**

- **목표**: Python AI 서버의 기능은 Flutter 앱을 통해 직접 테스트합니다.
- **수행 내용**:
    - Flutter 앱은 `192.168.0.187:8001` 주소를 통해 Python AI 서버와 직접 통신할 수 있으므로, Flutter 앱 내에서 AI 서버의 API를 호출하는 테스트를 진행합니다.
- **의의**: Java 서버를 거치지 않고 Python AI 서버의 기능 자체를 검증할 수 있습니다.

---

### 3. 향후 조치

- **환경 변경 시**: 개발 환경(PC 또는 네트워크)이 변경되어 `localhost` 또는 내부 IP 통신이 가능해지면, `MetricsOrchestrationController.java`의 주석 처리된 코드를 복원하여 전체 파이프라인을 통합 테스트합니다.
- **배포 환경**: 실제 서버 배포 환경에서는 이러한 네트워크 제약이 없을 것이므로, 모든 기능이 정상 동작할 것으로 예상합니다.

---

**결론적으로, 현재 환경의 제약을 인지하고, 개발의 우선순위를 조정하여 핵심 로직 개발에 집중하며, 가능한 경로를 통해 AI 서버 기능을 검증하는 유연한 전략을 채택합니다.**
